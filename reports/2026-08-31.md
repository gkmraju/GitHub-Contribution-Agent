## Selected opportunity

Repository: `abhigyanpatwari/GitNexus`

Issue: #2931 — `fix(swift): SPM target grouping takes the first path-prefix occurrence, so a repeated target prefix drops the file`

Problem: `groupSwiftFilesBySpmTarget()` used `indexOf(prefix)` and validated only the first textual occurrence of a target path. In a path such as:

`vendor/SubModules/Core/shim/Modules/Core/Thing.swift`

with target directory `Modules/Core`, the first occurrence is embedded inside `SubModules/Core` and therefore fails the segment-boundary check. The valid later occurrence is never examined, so the file falls into `__default__` instead of target `Core`.

This can affect same-module resolution consumers behind Swift SPM grouping, including implicit imports, target siblings, and sibling type bindings.

## Implementation

Change 1 — `gitnexus/src/core/ingestion/languages/swift/target-grouping.ts`

Replaced the first-occurrence logic:

`indexOf(prefix)` + boundary check

with segment-aware matching:

- `normalized.startsWith(prefix)`
- or `normalized.includes('/' + prefix)`

This allows a later valid segment-aligned occurrence to match while still refusing partial path segments.

The existing first-target-wins behavior is preserved.

Change 2 — focused unit coverage

Added `gitnexus/test/unit/scope-resolution/swift-target-grouping.test.ts` with three cases:

1. Repeated-prefix reproduction from issue #2931 resolves into the `Core` target.
2. A partial segment such as `SubModules/Core` does not incorrectly match `Modules/Core`.
3. Overlapping target paths continue to obey first-target-wins semantics.
