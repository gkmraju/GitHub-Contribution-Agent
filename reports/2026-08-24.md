## Selected opportunity
### langchain-ai/deepagents #5781
The repair middleware exists specifically to make incomplete historical tool-call turns safe to replay. OpenAI Responses content blocks create another representation of a tool call that can survive even when LangChain's normalized `tool_calls` list has been cleared. Because the middleware ignores that representation, a single interrupted/cancelled turn can poison a persisted thread and repeatedly trigger a provider 400 on subsequent invocations.

### Why it matters
This is reliability/recovery infrastructure rather than a cosmetic change. A correct fix would let persisted agent sessions recover from a real partial-turn state instead of becoming permanently unusable. The issue is also narrowly testable without a live model: construct an `AIMessage` with a Responses `function_call` content block and no normalized tool call, run the middleware, and verify a matching synthetic `ToolMessage` is inserted exactly once.

## Expected implementation direction
Subject to maintainer assignment/direction:
- teach the middleware to extract supported Responses/v1 `function_call` content blocks from `AIMessage.content`;
- use `call_id` as the tool-call identity and `name` for the synthetic result;
- preserve existing normalized `tool_calls`/`invalid_tool_calls` behavior;
- avoid double-patching when the same call is represented in both normalized metadata and content;
- preserve block/message order and generate one synthetic result per unanswered call;
- add focused regression tests for content-only orphan, already-answered content call, mixed normalized/content representations, and duplicate identity handling.
