## Source and duplicate / maintainer checks

Issue #2931 remains open and documents the original bug: first-occurrence prefix matching could drop files when the same target text appeared earlier inside a longer path segment. The issue explicitly recommends segment-aware matching using a starts-with or `/<prefix>` containment shape.

The current upstream PR diff was fetched directly. It shows that PR #3105 already uses:

`normalized.startsWith(prefix) || normalized.includes(`/${prefix}`)`

and does not use `lastIndexOf`. Therefore the bot's specific P2 explanation was stale or inconsistent with the current PR diff rather than a real defect in the present implementation.

No duplicate implementation was introduced in this run; the work stayed on the existing issue-linked Draft PR.
