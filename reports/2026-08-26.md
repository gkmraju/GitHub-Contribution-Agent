## Selected opportunity — paperclipai/paperclip #11856

Issue: https://github.com/paperclipai/paperclip/issues/11856

Problem: Paperclip's canonical deployment guide explains `local_trusted`, `authenticated/private`, and `tailnet` binding, but does not tell operators that onboarding persists the selected server/auth settings to the instance configuration. That omission caused a user to believe Tailnet/authenticated flags must be repeated on every start or manually added to the background service command.

### Evidence that the defect still exists

Current `doc/DEPLOYMENT-MODES.md` documents the Tailnet mode and gives `npx paperclipai run --bind tailnet` as an example, but does not state that onboarding's selected settings persist or that later plain service starts reuse them.

Current `cli/src/commands/onboard.ts`:

1. Resolves the selected bind and auth preset into `server` and `auth` configuration.
2. Builds the full `PaperclipConfig`.
3. Calls `writeConfig(...)` before completing onboarding.
4. Shows plain `paperclipai run` as the normal next command.
5. Can hand off to an installed background service after saving the configuration.

This makes the requested documentation clarification evidence-backed rather than speculative.

## Implementation

Created branch from current upstream `master` commit `ca02d2463af3626ca05e05e4e7572b23444fb256`:

- Branch: https://github.com/gkmraju/paperclip/tree/docs/tailnet-config-persistence

Changed exactly one file:

- `doc/DEPLOYMENT-MODES.md`

The change now states that:

- onboarding saves reachability and authentication choices in the instance `config.json`;
- later `paperclipai run` invocations, including background-service starts without reachability flags, use that saved configuration;
- users do not need to repeat Tailnet/authenticated-private selection on every start;
- `configure --section server` follows the same interactive behavior and saves updated server configuration.
