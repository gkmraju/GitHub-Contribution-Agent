### Evidence and duplicate checks

Issue #12226 reports the managed installer failing on an npm response shaped as a single-element JSON array, for example:

```text
npm returned an unexpected version response: [
  "2026.824.1"
]
```

Current `master` resolves the npm version in `cli/src/commands/install.ts`. `parseResolvedVersion()` accepts a JSON string but rejects an array, even when the array contains exactly one version. A repository-wide PR search for `12226` returned no competing pull request. The issue has no maintainer comments. `CONTRIBUTING.md` was inspected before implementation; it asks contributors to prefer small focused fixes, search for duplicates, use the PR template, link public issues, document AI assistance, and add validation evidence.

This is a narrow bug with direct user impact: a valid npm CLI response shape can stop the official managed install/update flow before the package payload is downloaded.

## Expected impact

Users whose npm client/registry interaction returns a one-element JSON array for the version field should no longer have managed installation or update aborted as an unexpected response. The parser remains intentionally strict when npm returns more than one candidate version, preventing silent selection from an ambiguous result.

## Skills and concepts learned

- npm CLI JSON output can vary between a scalar and an array shape for similar metadata queries.
- Boundary parsers should normalize known equivalent response shapes without silently accepting ambiguous data.
- Regression tests are most useful here when they assert both the new accepted case and the intentionally rejected near-neighbor case.
