## 4. Selected opportunity and evidence

**Issue:** [9Router #5363 — binary image MIME mismatch](https://github.com/decolua/9router/issues/5363), opened **2026-11-01 01:46:59 UTC**. The reporter observed `Content-Type: image/png` with actual JPEG bytes `FF D8 FF E0` for multiple Cloudflare FLUX/Leonardo models. This silently mislabels generated files for clients that derive extensions from the response header. A Cloudflare SDXL PNG case was reportedly correct.

**Root cause verified in source:** [imageGenerationCore.js](https://github.com/decolua/9router/blob/master/open-sse/handlers/imageGenerationCore.js) derived binary MIME and `Content-Disposition` from `body.output_format || "png"` in two separate response paths, rather than the returned bytes. [mediaConfig.js](https://github.com/decolua/9router/blob/master/open-sse/config/mediaConfig.js) already contained PNG/JPEG/GIF/WebP/BMP signatures. The [Cloudflare adapter](https://github.com/decolua/9router/blob/master/open-sse/handlers/imageProviders/cloudflareAi.js) normalizes base64 image data, leaving the core responsible for binary response headers.

**Duplicate/maintainer screening:** Queried open/closed PRs for binary image MIME/JPEG and issue #5363; no competing targeted PR was found. Inspected README, `CLAUDE.md`, `open-sse/AGENTS.md`, `tests/README.md`, existing `tests/unit/image-generation.test.js`, and root `package.json`. `CONTRIBUTING.md` was absent. Project conventions favor ESM, existing configuration, focused tests and conventional commits. The current upstream `master` head was `1fe586bb1cf35e1ed0cb2150a8ef7d1db040b21d` (v0.5.112).

## 5. Execution-readiness and implementation

Changes:
- Added `open-sse/handlers/imageBinaryResponse.js` to match returned image bytes against the existing configured signatures, including WebP RIFF/WEBP verification; unknown signatures use `application/octet-stream`.
